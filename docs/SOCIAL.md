## 0. Honesty rules (read first)

* **No real platform was contacted, ever.** Every platform needs the **owner's own developer app and keys**, which nobody here has. The adapters are written against the platforms'
  documented public APIs and tested ONLY against the local mock `bin/dev/mock-social.php` (and a test transport). A green test proves OUR code, not the real service: **never claim
  a platform works live before the owner has seen a real test post appear** ("Test connection" then "Send a test post" in Admin > Social media > Channels; the admin screen says so).
* **Nothing is posted anywhere until the owner has set a channel up.** Every channel starts OFF and empty; no key, token or secret is seeded. The global switch and a switch per channel exist.
* **Platform realities the design respects** (state them in the UI too):
  * **Facebook**: a Page post through the Graph API with a **Page access token**. While the Meta app is in Development mode only people with a role on the app may see what it posts; going Live may need Meta business verification / app review.
  * **Instagram**: only **Business / Creator** accounts **linked to a Facebook Page**; needs a **publicly reachable image URL** (we host one at an unguessable address); two steps (container, then publish); **no clickable links in captions** (the templates say "link in bio"); the picture must be a JPEG between 4:5 and 1.91:1 (our square 1080x1080 is fine).
  * **X**: API v2 `POST /2/tweets`, 280 **weighted** characters, **every URL counts 23**; OAuth 1.0a user-context signing (recommended) or an OAuth 2.0 user bearer token (expires after ~2 hours, cannot be refreshed by this site). X may require a paid API plan for posting.
  * **LinkedIn**: posting as an **organisation** needs the `w_organization_social` permission (the "Community Management API" product, which LinkedIn reviews). Tokens last **~60 days**; refresh tokens exist only for partner programmes: the admin pastes a new token and enters its expiry date (reminder 14 days before).
  * **Telegram**: the Bot API (`sendPhoto` / `sendMessage`) to a channel the bot administers. No review.
  * **TikTok: NO direct channel is built, on purpose.** TikTok's Content Posting API only accepts **video** (or photo posts from apps TikTok has **audited**); an app that is not audited can only create **private drafts**; and it cannot carry a text + link newsletter. TikTok (and any other platform) is served by (a) the **webhook** channel (Zapier / Make / IFTTT / Buffer receive title, summary, link, image links and a ready TikTok caption) and (b) the **Share kit** (portrait 1080x1920 and square images + caption + link to post by hand in a minute).
* Captions are plain text. Deleting an issue does **not** delete posts already made on the platforms (the panel says so): no API call exists for that.

## 2. Data model (additive, idempotent)

* `newsletters.share_choices TEXT NULL`: the admin's choices, saved WITH the issue and used when it goes public: `{"facebook":{"on":true,"caption":""},"x":{"on":false,"caption":""}}`. `caption` is `""` while the admin did not change the template (so it follows later edits of the title); NULL = the panel was never saved (each channel's "share by default" setting applies). `newsletters.share_version INT UNSIGNED NOT NULL DEFAULT 1`: rises only on an explicit "Post again". Saving the choices changes neither `version` nor `updated_at` of the issue (no editing conflict).
* `social_posts` = the queue AND the share log: `id, newsletter_id (FK CASCADE), channel VARCHAR(20), share_version, status ENUM(queued, posting, posted, failed, skipped, review), caption TEXT, attempts, next_attempt_at, last_attempt_at, remote_id VARCHAR(190), remote_url VARCHAR(255), last_error VARCHAR(255), fail_code VARCHAR(20) NULL, posted_at, created_by (FK SET NULL), created_at, updated_at`. `fail_code` = `auth` when the platform rejected the access token / key (also when a stored secret cannot be read); NULL for every other failure. Added by a guarded, idempotent `ALTER` (`information_schema` check) after the `CREATE TABLE IF NOT EXISTS`, so a database that already has the table gets the column and nothing else changes, **UNIQUE (newsletter_id, channel, share_version)**, keys `(status, next_attempt_at)` and `(channel, status)`. Never a token, never a full API payload or response; `last_error` is a short redacted text.
* `social_images` (IMAGES agent writes it): `token CHAR(64) PRIMARY KEY` (256 random bits), `newsletter_id (FK CASCADE)`, `variant ENUM(square, portrait, landscape)`, `path` (relative to `storage/private/social`), `src_hash`, timestamps; **UNIQUE (newsletter_id, variant)**: re-rendering keeps the token, so an address a platform already holds stays valid.
* Dates are stored in the application time zone (Africa/Kampala) and compared against a timestamp bound by PHP (`PostQueue::now()`), never the database server's `NOW()`.

**Secrets**: settings key `social_secret_<channel>_<field>` = `enc:v1:` + base64url(iv | tag | ciphertext), **AES-256-GCM** through `SecretStore::encrypt/decrypt` (key derived from `APP_KEY`, so `APP_KEY` must be set in production and never changed; a changed key or a tampered value reads as "stored but cannot be read, enter it again"). The `.env` override of each secret **wins** and the admin screen then says "Set in the .env file (NAME)": `SOCIAL_FB_PAGE_TOKEN`, `SOCIAL_IG_TOKEN`, `SOCIAL_X_API_KEY`, `SOCIAL_X_API_SECRET`, `SOCIAL_X_ACCESS_TOKEN`, `SOCIAL_X_ACCESS_SECRET`, `SOCIAL_X_BEARER_TOKEN`, `SOCIAL_LI_ACCESS_TOKEN`, `SOCIAL_TG_BOT_TOKEN`, `SOCIAL_WEBHOOK_URL`, `SOCIAL_WEBHOOK_SECRET`. **The webhook address is a secret too** (field `url`, `.env` name `SOCIAL_WEBHOOK_URL`): Zapier / Make / IFTTT hook addresses ARE the credential (whoever holds one can post fake events into the organisation's automations), so it is stored encrypted, shown only as "Set (hidden)" and replaced or removed like a token. A value an older version saved as the plain setting `social_ch_webhook_url` keeps working (field flag `legacy`) and is encrypted, and the plain copy emptied, by `SocialConfig::migrateLegacySecrets()` (runs when the channels screen opens; idempotent; does nothing without OpenSSL). **Fail closed**: a secret that is stored but cannot be decrypted (the `APP_KEY` changed, or the value was tampered with) blocks the channel whether the field is required or optional (`ready()` = `needs_token`, "enter it again"; `missingFor()` lists it; the dashboard counts it; the adapters refuse to send): an optional webhook signing secret or Instagram token that silently dropped out would send UNSIGNED messages or use another account's token. A secret is **never** shown again after saving (only "Set (hidden)" / "Set in the .env file"), never in HTML, JSON, logs, the audit trail (field NAMES only), e-mails, error pages or the queue; `SocialHttp::redact()` blanks every configured secret and every credential-looking text in every error message. `SocialConfig::secret()` and `channelConfig()` (plaintext) are for adapters only.

`SocialConfig::ready($channel)` says whether a channel can post: `off` (global or channel switch) | `incomplete` (a required field is missing or unreadable) | `needs_token` | `expired` (token date passed) | `ready`. `availableIds()` lists the ready ones. `saveChannel()` refuses to switch a channel on while fields are missing.

## 4. Channels

`Channels::ids()` = `facebook instagram x linkedin telegram webhook` (display and posting order). Each adapter implements `ChannelInterface` (`id, meta, validate, test, post`) by extending `AbstractChannel` (metadata, format validation from the field specs). **META keys**: `id label icon short limit soft count (plain|x) links (clickable|none|attached) uses_image image_variant ambiguous (review|retry) needs setup_url steps permissions notes fields test_post (real|test_chat|webhook_flag) token_expiry built`. **Field spec**: `key label type (text|secret|select|date|url|multi) required when (['field'=>'value']) secret env pattern options default placeholder help maxlength`.

`post(array $config, SocialPayload $payload): SocialResult` and `test(array $config): array{ok,state,message,detail?}` must **never throw**, respect `$payload->deadline` (pass it as the `deadline` option of `SocialHttp`), and return only redacted texts. `SocialResult` states: **posted** | **transient** (nothing posted, a retry may work: backoff 60 s / 5 min / 15 min / 1 h / 3 h, `failed` after 5 attempts; `retryAfter` overrides) | **failed** (a retry will not help) | **auth** (token rejected: channel marked "needs a new token", admin told once) | **review** (AMBIGUOUS: the request may have been executed; never retried by itself). `SocialHttp::toResult($channel, $httpResult)` maps any failed HTTP answer to the right state; `describeFailure()` does it for `test()`.

**Ambiguity policy** (`meta['ambiguous']`): `review` for Facebook, Instagram (step 3), X, LinkedIn, Telegram (no idempotency key exists: a timeout after the request was sent, a dropped connection, HTTP 502 / 504 **and an HTTP 2xx answer that is not readable as `{"ok":true,...}`** end in **review**, and a person chooses "Mark as posted", "Post anyway" or "Skip"); `retry` for the webhook (every message carries `event_id` / `X-Lumina-Delivery`, so the receiver de-duplicates). The attempt is **recorded before the platform is called** (`status posting`, `attempts + 1`, `last_attempt_at`); a `posting` row older than 10 minutes (the process died) becomes `review` (webhook: `queued`).

### 4.1 Facebook Page (CHANNELS agent builds `post()` / `test()`; metadata frozen)
Fields: `page_id` (digits, required), `page_token` (secret, required, `SOCIAL_FB_PAGE_TOKEN`). Limit 5000 (soft 600), link attached as a card (the default template has no `{url}`).
Setup (plain language, shown in the admin): create a Meta app (type Business) at developers.facebook.com with the Facebook account that manages the Page; in the Graph API Explorer get a Page access token with `pages_manage_posts`, `pages_read_engagement`, `pages_show_list`; make it long-lived (Access Token Debugger > Extend, then `/me/accounts`: a Page token obtained that way does not expire); copy the Page ID and the token; Test connection; Send a test post.
Calls (host `graph.facebook.com`, `SocialHttp::api('facebook', ...)`, path `/{social_graph_version}/...`, token in the `Authorization: Bearer` header or the POST body, never in the URL): `test()` = `GET /{ver}/me?fields=id,name` (a Page token's `/me` is the Page) and `GET /{ver}/{page_id}?fields=id,name`; `post()` = `POST /{ver}/{page_id}/feed` form `message` (caption), `link` (`payload->plainUrl`) -> `{"id":"<page>_<post>"}`, `remote_url = https://www.facebook.com/<id>`. Graph error codes 190 / 102 / 463 -> auth (`SocialHttp::isAuthFailure`).

### 4.2 Instagram (CHANNELS agent)
Fields: `account_id` (digits, required), `token` (secret, optional, empty = the Facebook Page token; `SOCIAL_IG_TOKEN`). Limit 2200 (soft 1500), links not clickable, uses the **square** image.
Setup: Professional account (Business or Creator); link it to the Facebook Page; same Meta app plus `instagram_basic`, `instagram_content_publish`, `pages_show_list`; the ID comes from `GET /{page-id}?fields=instagram_business_account`.
Calls: `test()` = `GET /{ver}/{account_id}?fields=id,username`; `post()` = (1) `POST /{ver}/{account_id}/media` form `image_url` (`payload->imageUrl`), `caption` -> `{"id":"<creation id>"}`; no image -> `failed('no_image')`; (2) optionally poll `GET /{ver}/{creation_id}?fields=status_code` until `FINISHED` (about 6 s, `ERROR` / `EXPIRED` -> failed); (3) `POST /{ver}/{account_id}/media_publish` form `creation_id` -> `{"id":"<media id>"}` (NOT idempotent: an ambiguous timeout here is `review`, put the creation id in the result); permalink via `GET /{ver}/{media_id}?fields=permalink` (best effort).

### 4.3 X (CHANNELS agent; also builds `app/services/Social/OAuth1Signer.php`)
Fields: `mode` (select `oauth1` default | `bearer`), `api_key`, `api_secret`, `access_token`, `access_secret` (secrets, required when `mode = oauth1`), `bearer_token` (secret, required when `mode = bearer`). Limit 280 weighted (`count = x`).
Calls (host `api.x.com`, second accepted host `api.twitter.com`): OAuth 1.0a: use the `authorize` option of `SocialHttp::api()`: a `callable(method, url, query, form): array` called with the **exact final URL** (the dev base included) that returns the `Authorization: OAuth ...` header (HMAC-SHA1; a JSON body is NOT part of the signature base string); `test()` = `GET /2/users/me`; `post()` = `POST /2/tweets` json `{"text": caption}` -> 201 `{"data":{"id","text"}}`, `remote_url = https://x.com/<username>/status/<id>`. Duplicate text answers 403 (failed). The mock **verifies the signature** (and refuses a replayed nonce, an old timestamp or a signature over another URL), so the signer is really tested.

### 4.4 LinkedIn (CHANNELS agent)
Fields: `org_urn` (`urn:li:organization:123`, a bare number is accepted and prefixed by `normaliseConfig`), `access_token` (secret, `SOCIAL_LI_ACCESS_TOKEN`), `expires` (date, optional: **reminder on the dashboard and by e-mail 14 days before**, and the channel is "expired" after it). Limit 3000 (soft 700).
Calls (host `api.linkedin.com`; headers `Authorization: Bearer`, `X-Restli-Protocol-Version: 2.0.0`, `Linkedin-Version: <social_li_version>`): `test()` = `GET /rest/organizationAcls?q=roleAssignee&role=ADMINISTRATOR` (the URN must be among the elements; 200 without it = "not an administrator of that page"); `post()` = `POST /rest/posts` json `{author: org_urn, commentary, visibility: "PUBLIC", distribution: {feedDistribution: "MAIN_FEED", targetEntities: [], thirdPartyDistributionChannels: []}, content: {article: {source: plainUrl, title, description}}, lifecycleState: "PUBLISHED", isReshareDisabledByAuthor: false}` -> 201, the new post URN in the **`x-restli-id` response header** (`SocialHttp` lower-cases header names), `remote_url = https://www.linkedin.com/feed/update/<urn>`. Escape `( ) [ ] { } < > @ | ~ _ * # \` in `commentary` with a backslash ("little text" format). 401 / `REVOKED_ACCESS_TOKEN` -> auth. The legacy `POST /v2/ugcPosts` is an acceptable fallback (the mock has it too).

### 4.5 Telegram (built, reference implementation)
Fields: `bot_token` (secret, required, `^\d{5,}:[A-Za-z0-9_-]{20,80}$`), `chat` (`@name` or `-100...` id, required), `test_chat` (optional: where "Send a test post" goes). Limit 1024 (soft 800), square image.
`test()` = `getMe`, `getChat(chat)`, and for a CHANNEL `getChatMember(chat, bot id)` must say `administrator` / `creator`. `post()` = `sendPhoto {chat_id, photo, caption}` (caption cut at 1024) with an image, else `sendMessage {chat_id, text}`; **plain text, no parse_mode**; a 400 about the picture falls back once to `sendMessage` (a 400 posted nothing); `remote_url = https://t.me/<username>/<id>` or `https://t.me/c/<internal id>/<id>`; 429 -> transient with `parameters.retry_after`. The test post is one `sendMessage` to the test chat (else the real chat), never an image. The bot token is part of the URL path (Telegram's design): `SocialHttp` never logs or returns URLs.

### 4.6 Webhook (built, reference implementation; also the route for TikTok)
Fields: `url` (https, **SSRF guarded**, also checked when saved; a SECRET field, see 3), `secret` (optional signing secret; unreadable = the channel stops, never an unsigned message), `fields` (multi: which fields to send; empty = all).
`POST` JSON with `Content-Type: application/json`, `X-Lumina-Event` (`newsletter.published` | `test.ping`), `X-Lumina-Delivery` (the event id, `lumina-post-<id>`), `X-Lumina-Timestamp` (unix seconds), and, when a secret is set, **`X-Lumina-Signature` = hex HMAC-SHA256 of the exact request body with the secret**. Body: `{"event","event_id","timestamp" (inside the signed body, so receivers can refuse old messages),"test":bool,"site", title, summary, url (with UTM) + plain_url, images {square,portrait,landscape} + image_url, captions {facebook,instagram,x,linkedin,telegram,tiktok,default}, hashtags [..], issue_number, date}` (only the chosen fields besides the fixed ones). A receiver verifies: recompute the HMAC over the raw body, compare in constant time, check `timestamp` is recent, drop a repeated `event_id`. Success = any 2xx; an ambiguous timeout is retried (policy `retry`).

## 5. State machine, hook and dispatcher

```
queued ──claim──► posting ──posted──► posted
   ▲                 ├──transient──► queued (next_attempt_at = now + backoff; failed after the 5th attempt)
   │                 ├──failed / auth──► failed        (auth also marks the channel "needs a new token")
   │                 └──ambiguous──► review
retry (admin) ◄── failed | skipped | review ──skip (admin)──► skipped        review ──"Mark as posted" (admin)──► posted
```
* **Hook** (`ShareHook::onWentLive($id, $source, $userId, $firstTime)`, never throws): the issue becomes public through `NewsletterService::transition(.. published)` or the lazy `resolveScheduled()`. It acts only when the global switch is on, the issue is really public and it is the **first time** it goes public (`published_at` was empty; an issue that was public before the module existed is never shared by surprise: use "Share now"). For every ready channel the saved choice decides (panel never saved: the channel's default); a row is created **once** (`PostQueue::enqueue`, UNIQUE; a channel that already has ANY row for the issue is left alone, so unpublish + republish never posts again); then `SocialDispatcher::afterResponse($id)` runs the posts **right after the HTTP response has been sent** (`App::afterResponse`: `fastcgi_finish_request` / `litespeed_finish_request`, session released; a public visitor's request that flips a scheduled issue only does so where the host can detach, otherwise cron picks it up; in the CLI it runs at once). Publishing is never delayed or broken: every error is logged (redacted) and swallowed (tested with a channel whose metadata throws).
* **Budgets**: per channel connect 4 s and total 10 s, channels in sequence (order of `Channels::ids()`), **25 s** for the whole immediate run (12 s where the host cannot detach). Rows that did not get their turn stay queued; a run with no time left puts the row back WITHOUT counting the attempt.
* **Cron** `bin/social-dispatch.php` (hPanel, every 5 minutes: `0-59/5 * * * *  php .../bin/social-dispatch.php > /dev/null 2>&1`): `SocialDispatcher::runDue()` under the named lock `lumina_social_dispatch` (two runs never overlap), reclaims stuck rows, sends the one-time e-mails, attempts due rows (a channel that just failed is not hammered again in the same run). Needs `APP_URL`. **Lazy retry** `SocialDispatcher::lazyRetry()` on admin page loads: at most once a minute (a stamp file `storage/cache/social-lazy.stamp`, no database read in between), only when there is work, after the page was sent.
* **Auth failures** (`SocialResult::auth`): the post is `failed` with `fail_code = 'auth'`, the channel's status becomes `needs_token` (not offered, nothing else is attempted on it), the admin is e-mailed **once** per episode (`Mailer::notify`, no token in the text) and the dashboard shows "Social media needs attention" (and the sidebar badge); pasting a new token (or a new webhook address) resets the status and "notified"; the channels controller then re-queues, through `PostQueue::retryAuthFailures($channel)`, ONLY the posts of that channel with `fail_code = 'auth'`, made in the last **48 hours**, of issues that are **still public** (a refused picture, a duplicate, a permission problem, "gave up after 5 tries" and old issues, which the admin may have posted by hand with the Share kit, are never re-queued: each has its own Retry), and the message names the issues. A channel that BORROWS a secret starts over too: replacing the Facebook Page token resets Instagram (status, "notified") when Instagram's own token box is empty and re-queues its auth failures (`SocialConfig::dependents()`, `saveChannel()['reset']`). A re-queued post (this and every Retry / Post anyway) takes its caption AGAIN from the issue's saved choices (what the admin edited after the failure) or the template: `PostQueue::freshCaption()`.
* **Kill switches**: `social_enabled` (global) and `social_ch_<channel>_enabled`; a queued post of a switched-off channel is skipped (with the reason) and can be retried after switching it on.
* **Share now / Post again** (explicit actions of the panel): `ShareHook::shareNow()` queues only channels never posted for this public issue; `ShareHook::postAgain()` raises `share_version` and queues one new row per channel that had a post (needs `confirm`). **Post again is idempotent**: the decision is made under the named lock `lumina_social_again_<id>` (state re-read inside it), the request carries the `share_version` the panel showed (`share_version` in the body; another tab or a double click that already raised it is refused with 409 "already posted again"), the raise is a compare-and-swap (`UPDATE ... WHERE share_version = <seen>`, one row or nothing), a channel whose newest post is younger than `ShareHook::AGAIN_COOLDOWN` (120 s) is refused ("posted a moment ago"), and a platform that rejects identical text (meta `repeat_text = rejected`, X) needs an edited caption (refused with the reason; the panel warns beforehand with `again_note`). Tested with four PHP processes at the same instant: one extra post, not three.
* Audit: `social.share.queued|choices|now|again`, `social.channel.update|test|send_test`, `social.profiles.update`, `social.settings.update`, `social.templates.update`, `social.card.update`, `social.post.retry|retry_anyway|skip|mark_posted`: ids, channel names and field NAMES only.

## 6. `SocialHttp` (the ONE outbound client)

* **Platform APIs** (`SocialHttp::api($channel, $method, $path, $opts)`): HTTPS only, fixed hosts (`API_HOSTS`: graph.facebook.com, api.x.com / api.twitter.com, api.linkedin.com, api.telegram.org), TLS verification always on (cURL `VERIFYPEER` + `VERIFYHOST 2`; the stream fallback verifies peer and name), **no redirect is ever followed** (a 3xx is an error), path validated (`/...` only, no `//`, `..`, spaces, query), methods GET / POST, header names and values checked, answer capped at 1 MB, connect 4 s / total 10 s clamped to the caller's `deadline`. Options: `query`, `headers`, `json`, `form`, `body` + `content_type`, `host`, `connect_timeout`, `timeout`, `deadline`, `authorize` (callable, see 4.3). `SocialHttp::urlFor()` returns the exact address.
* **Webhook** (`SocialHttp::webhook($url, $body, $headers, $opts)`; **redirects**: 301 / 302 / 303 are never followed (a POST is not repeated somewhere else; the admin pastes the final address), 307 / 308 only to the SAME host and port (each hop re-validated), at most 2; anything else is an error of kind `redirect`, so the signed body and the `X-Lumina-Signature` headers never reach a host the admin did not enter): `guardWebhookUrl()`: https only, port **443 / 8443**, no user info (also `@` tricks), a real host name (no `localhost`, single-label, numeric / octal / hex / short IP spellings such as `2130706433`, `0x7f.1`, `127.1`, no `.local .internal .localhost ...`) or a canonical public IP literal; **DNS resolved for IPv4 and IPv6 and EVERY answer must be public** (private, loopback, link-local, CGNAT, documentation, benchmarking, multicast, reserved; IPv6 allowed only inside `2000::/3` minus documentation / Teredo / 6to4, so IPv4-mapped, NAT64, unique-local and link-local are refused); the request is **pinned** to the validated address (cURL `RESOLVE`; the stream fallback connects to the IP with the host name as TLS peer name): no second lookup, so DNS rebinding cannot help; **at most 2 redirects (307 / 308, same host only), each hop re-validated from scratch**. Test hooks: `SocialHttp::$resolver` (host -> IPs) and `SocialHttp::$transport` (replaces the network).
* **Result** of both: `{ok, status, json, raw, headers (lower-case), error (safe text), kind ('' | blocked | timeout | network | tls | too_large | redirect | budget), ambiguous, retry_after, ms}`. `ambiguous` = the request may have been executed: a timeout or dropped connection AFTER it was sent, HTTP 502 / 504. `raw` is the body: callers must not log it. Failures are logged by host, method, status and kind only (never a URL, header or body).
* **Dev only**: with `APP_ENV=local`, `SOCIAL_DEV_BASE_URL=http://127.0.0.1:PORT` (127.0.0.1 / localhost / [::1], no path, query or credentials) sends the platform calls to the mock under `/graph /x /linkedin /telegram` and lets a webhook URL under `<base>/webhook` through the guard (other local addresses stay blocked). Ignored in every other environment (a test proves it).

## 7. Captions (`CaptionBuilder`)

Placeholders (one pass, so a title containing `{url}` stays literal; unknown ones are reported and left as they are): `{title} {summary} {url} {issue_number} {date} {hashtags} {site}`. `{url}` gets the UTM tags when `social_utm` is on; `{issue_number}` is just the digits (empty without a number); `{date}` reads "20 October 2026". Built-in templates (`DEFAULT_TEMPLATES`): facebook `{title}\n\n{summary}\n\n{hashtags}`; instagram ends with "Read the full newsletter: link in bio."; x `{title}\n{summary}\n{url}\n{hashtags}`; linkedin / telegram / webhook include `{url}`; tiktok (kit) "Link in bio.".
**Limits** (hard, `Channels::get($id)->meta()['limit']`): facebook 5000, instagram 2200, **x 280 weighted** (a URL counts 23; characters above U+10FF other than the usual punctuation ranges, so emoji and CJK, count 2), linkedin 3000, telegram 1024, webhook 5000, tiktok 2200. `CaptionBuilder::length($channel, $text)` is the one counter (the panel's `/share/count` endpoint calls it; the mock uses its own implementation and a test proves they agree). A **template** result that is too long is SHRUNK (summary first at a word boundary with "...", then the hashtags are left out, then the title); a caption an admin **typed** is never shortened silently: `validate()` reports it and saving is refused. Templates are checked when saved (`SocialConfig::saveTemplates`): known placeholders only, `{title}` or `{summary}` present, and the fixed words must leave room (`fixedLength()`).
**Plain text**: `sanitize()` removes real markup only (comments, processing instructions and complete tags of known HTML elements, twice: after decoding entities), NOT everything after a `<`, so "Dropout rate <5% after our programme", "I <3 Uganda", "x<y" and "<$1/day" survive (the text of removed tags stays); decodes entities, removes control characters, zero-width characters, bidirectional overrides / isolates and tag characters, repairs invalid UTF-8, folds line breaks (single-line fields) or keeps at most one blank line. Hashtags: letters, digits, underscores only, no pure numbers, no duplicates. Telegram is sent as plain text (`CaptionBuilder::telegramHtml()` exists for anyone who needs HTML mode).

## 14b. Audit fixes (what changed after the independent review)

Share panel: the panel shows the REAL caption (read-only) of a channel whose post is queued, being posted or posted, and keeps the caption editable after a failure / skip / review (a retry sends the saved text; the edit can be saved even while the channel needs a token); the publish dialog lists channels from the LIVE state of the boxes, saves the choices first, reads the answer of that save and says which typed caption was NOT saved (the newsletter editor waits for `detail.ready` before it opens the dialog); a refused save is never silent. Counters: every counter is linked to its box (`aria-describedby`), `aria-invalid` is set when over, ONE debounced `role="status"` message says when a box goes over or back (no `aria-live` on the panel body or the sample caption). Profile links: no quotes, `< >`, backslash or backtick; a WhatsApp number may be typed with spaces / `+` / `00` and needs its country code (no leading 0). Channel screen words: "Set up, not tested" until a test works, "Tested OK" after; status words are not Title-Cased. Scheduled issues show "23 Oct 2026, 21:29 (Kampala)". Newsletter e-mail: the "Follow us:" words are a registry field (`email.follow`, may be emptied). Default profile order: LinkedIn before X (as before the module existed). ## 15. Owner to-do, known limits, risks

1. Create the platform developer apps / bots yourself (the steps are on Admin > Social media > Channels), paste the keys, **Test connection**, then **Send a test post** on every channel before relying on it. Nothing here has run against a real platform.
2. Put the profile links in Admin > Social media, choose where they show; confirm the default hashtags and the wording of the templates.
3. Set `APP_URL` / `APP_KEY` in the live `.env`, add the cron job, keep `.env` free of tokens unless you prefer `.env` to the encrypted admin fields.
4. TikTok: use the Share kit or an automation tool through the webhook; there is no direct TikTok posting by design.
* **Risks / limits**: (a) all six adapters and the share-image renderer are built and tested ONLY against `bin/dev/mock-social.php` (never a real platform: the owner's first test posts are the real test); (b) without the PHP GD extension (FreeType + JPEG) the cover photo or the bundled logo is sent as it is, and Instagram refuses a PNG or a picture outside 4:5 to 1.91:1; (c) a host without `fastcgi_finish_request` / `litespeed_finish_request` posts after the response only for signed-in admins (12 s) and otherwise leaves it to cron; (d) Meta / LinkedIn / X change their APIs, versions and review rules: the API version settings exist for that; (e) an ambiguous timeout needs a human decision by design (a rare duplicate is safer than a silent loss, and a silent duplicate is worse than a visible "needs review"); (f) deleting an issue does not delete remote posts; (g) token expiry is only known for LinkedIn (the admin types the date); Facebook Page tokens obtained as described do not expire but a revoked one is detected by the first failed post or by Test connection.
