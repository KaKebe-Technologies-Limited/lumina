## 3. Web layer and URLs

* `.htaccess` is an ALLOW-LIST: only real files below `assets/` and `uploads/` are served directly; everything else is rewritten to `index.php`
  even when a file of that name exists (so a stray `backup.zip`, `error_log`, `dump.sql.gz` in the project root is answered with 404 by the app).
  It also denies: `app/ bin/ database/ docs/ scss/ storage/ tools/ vendor/ tests/ .git`, dotfiles, `*.env *.sql *.md *.py *.log *.ini *.bak *.sh *.lock *.scss *.eml`,
  and every `.php` except `index.php`. Each of those folders also has its own deny-all `.htaccess`. `assets/.htaccess` serves only css/js/images/fonts;
  `uploads/.htaccess` disables script execution and only serves `jpg jpeg png gif webp ico`.
* **Host header**: `Request::host()` validates the Host header. `APP_URL` is REQUIRED when `APP_ENV` is not `local` (otherwise the app answers 500 with a
  log line); in production a Host that is not the `APP_URL` host or in `ALLOWED_HOSTS` gets 400. With `APP_URL` empty (local dev only) the host must look like a dev host
  (localhost, 127.x, private network, single-label, `*.test`/`*.local`/`*.localhost`). `origin()`/`abs_url()` (canonical, sitemap, e-mail links) use `APP_URL` when set.
* **Client IP**: `Request::ip()` reads `X-Forwarded-For` only when `REMOTE_ADDR` matches `TRUSTED_PROXIES` (IPs or CIDR, comma list) and then takes the first hop
  from the RIGHT that is not itself a trusted proxy. `TRUSTED_PROXIES` is mandatory behind a reverse proxy/CDN (otherwise all visitors share one IP and one rate limit).
* **Lazy session**: `Session::start()` only starts a session when the request carries a session cookie whose file exists. Reads never start one; the first write
  (`put`, `flash`, `regenerate`) does. Anonymous page views, `robots.txt`, `sitemap.xml`, 404s and bots therefore set no cookie and create no file. PHP's cache
  limiter is off (`Response` sends `Cache-Control: private, max-age=0, must-revalidate` for public HTML, `private, no-store` for `/admin`), and the save path
  `storage/sessions` is garbage-collected by PHP itself (`gc_probability=1`, `gc_divisor=100`). `Csrf::token()` gives cookie-less public visitors a signed
  stateless token (6 h); `/admin` always uses the session token. Never call `Session::get()` expecting it to create a session.
* **First administrator without a shell**: import `database/schema.sql` with phpMyAdmin (it no longer contains `CREATE DATABASE`/`USE`), set `INSTALL_TOKEN` (16+ chars)
  in `.env`, open `/install`, then remove the token. `/install` answers 404 unless the token is set AND the `users` table is empty.
* **Never hardcode `/lumina`.** The base path is computed at runtime (`dirname(SCRIPT_NAME)`), so the site works at `http://localhost/lumina/`,
  at a domain root, or in any sub-folder. Build every URL with `url()`, `asset()`, `upload_url()`, `img_url()`, `route()`, `link_url()`.
  In CSS use relative `url(...)` only for inline data URIs (no static paths in SCSS).
* Security headers (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, CSP, HSTS on https) are sent by
  `Response::send()`. **CSP forbids inline `<script>` and `on*=` handlers** (JS lives in `assets/js/*.js`; inline `style=""` is allowed;
  Google Fonts and Google Maps/YouTube iframes are allowed; analytics only when `analytics_id` is set).
* A failed CSRF check is sent as HTTP **403** (title "Page expired"). Apache turns non-standard 419 into 500, so views receive `$status = 419` but
  the wire status is 403.
* Themed error pages (B2): the error handler renders `app/views/web/errors/<status>.php`, else `web/errors/error.php` (503 first tries `web/errors/maintenance.php`), inside `layouts/main`, with variables `$status` (int), `$title`, `$message` (default copy; B2 may replace it with registry/DB copy), `$debug` (null unless APP_DEBUG). If none exists a built-in plain page is used. Admin requests and JSON requests get compact errors.
* Maintenance: `.env APP_MAINTENANCE=1` shows `web/errors/maintenance` (HTTP 503) to the public; `/admin` and logged-in users keep working.

## 4. Request lifecycle

`index.php` -> `bootstrap.php` -> `App::run()`: capture `Request` -> `Session::start()` -> load every `app/routes/*.php` (alphabetical: `admin_content`,
`admin_core`, `admin_inbox`, `admin_org`, `web_content`, `web_core`, `web_org`, `zz_custom_pages`) -> maintenance gate -> `Router::dispatch()`
-> middleware chain -> controller method `($request, ...$routeParams)` -> `Response::send()`.
`HttpException` / `ValidationException` / any `Throwable` are turned into responses inside `App::run()`; with `APP_DEBUG=0` visitors only ever see a
friendly page (and the exception goes to `storage/logs/app-YYYY-MM-DD.log`).

## 5. Core classes (`app/core`, namespace `App\Core`)

The full, **generated** signature list is in the *API reference* at the end of this file. Narrative rules and examples:

### Routing (`Router`, `Route`, `Middleware`)
```php
// app/routes/web_content.php  ($router is in scope)
use App\Controllers\Web\BlogController;
$router->get('/blog', [BlogController::class, 'index'])->name('blog.index');
$router->get('/blog/{slug}', [BlogController::class, 'show'])->name('blog.show');       // {slug}=[a-z0-9-]+  {id}=digits (cast to int)
$router->post('/contact', [ContactController::class, 'send'])->middleware(['honeypot', 'throttle:5,600']);
$router->group(['prefix' => 'admin', 'middleware' => ['auth']], function ($router) {
    $router->get('/posts', [PostController::class, 'index']);                              // -> /admin/posts
    $router->group(['middleware' => ['role:admin']], function ($router) { /* admin-only */ });
});
```
* Placeholders: `{id}` `\d+`, `{slug}` `[a-z0-9]+(-[a-z0-9]+)*`, `{token}`, `{year}`, `{month}`, `{path}` (`.+`); override with `->where('x', 'regex')`.
* **Static routes beat dynamic ones regardless of file order** (`/admin/pages/create` before `/admin/pages/{slug}`). Identical paths: first registered wins - so never
  register a path another agent owns (URL map, section 16).
* Handler = `[Controller::class, 'method']` or `'Class@method'` or a closure. Called as `$controller->method(Request $request, ...$params)` in path order; `{id}` arrives as `int`, others as `string`. Return a `Response` (or a string = HTML, array = JSON).
* **Middleware names** (comma-separated args after `:`): `csrf` (automatic on every POST/PUT/PATCH/DELETE - never add it yourself), `auth` (signed in; forces
  `/admin/profile/password` while `must_change_password`), `guest`, `role:admin` / `role:admin,editor`, `can:<ability>` (see abilities below),
  `throttle:<max>,<seconds>` (per IP+method+path; 429), `page.published:<slug>` (404 when the page row is unpublished), `honeypot` (bots get a fake success + redirect).
* `$router->fallback($handler)` registers the catch-all used only when **no route matched** a GET/HEAD (custom CMS pages, `zz_custom_pages.php`).
* **Abilities** (`config('abilities')`, `can('x')`, middleware `can:x`): `dashboard.view pages.edit pages.delete menus.manage settings.manage users.manage audit.view
  content.manage content.delete inbox.manage inbox.delete export.csv`. Roles: `admin` has all; `editor` has `dashboard.view pages.edit content.manage content.delete inbox.manage export.csv`
  (**not** `pages.delete menus.manage settings.manage users.manage audit.view inbox.delete`). Controllers call `$this->authorize('ability')` (403) or routes use `->middleware('can:...')`.

### Controllers
* Public: `class XController extends App\Core\Controller`; admin: `extends App\Core\AdminController` (routes inside the `auth` group). Constructor receives the `Request` (`$this->request`).
* `$this->renderPage('about', 'web/about/index', $data, $opts)` renders a CMS page: 404 if unpublished, SEO from `page_meta('about')`, view gets `$meta`, `$page`, `$breadcrumbs`, `$bodyClass`, `$request`.
  `$opts`: `meta` (override title/description/og_image/og_type/robots/canonical), `breadcrumbs` (`[[label, url|null], ...]`; Home is prepended automatically), `bodyClass`, `status`, `layout`.
  Detail page example: `renderPage('blog', 'web/blog/show', ['post'=>$p], ['meta'=>['title'=>$p['title'],'description'=>$p['excerpt'],'og_image'=>$p['cover_image'],'og_type'=>'article'], 'breadcrumbs'=>[['Blog', url('blog')],[$p['title'], null]]])`
  (breadcrumb *labels* for section roots come from `content()`/nav label, not hardcoded strings: use `SitePages::get('blog')['nav_label']`).
* `$this->render($view, $data, $opts)` = no published check / no page meta (admin, errors).
* `$this->validate(['email' => 'required|email'], $messages, $labels, $redirectTo)` returns validated data or throws `ValidationException` -> `App::run()` flashes errors + old input and redirects back (422 JSON for AJAX). `$this->fail(['field' => 'message'])` does the same manually. Views then use `error('field')`, `old('field')`.
* Admin: `render($view, $data, ['title' => 'Posts', 'nav' => 'posts', 'breadcrumbs' => [['Posts', null]]])` - `nav` = the sidebar item key to highlight; `$this->authorize('content.manage')`; `$this->audit('post.update', 'post', $id, 'Edited "..."')`; `$this->perPage()`.

### Database (`Database`) - PDO, exceptions, utf8mb4, **prepared statements only**
```php
$rows = Database::all('SELECT * FROM posts WHERE status = ? ORDER BY published_at DESC LIMIT ?', ['published', 10]);
$row  = Database::one('SELECT * FROM users WHERE email = :e', ['e' => $email]);
$n    = Database::value('SELECT COUNT(*) FROM posts', [], 0);
$id   = Database::insert('faqs', ['question' => 'Q', 'answer' => 'A']);   // column names are trusted identifiers, never user input
Database::update('faqs', ['answer' => 'B'], 'id = ?', [$id]);
Database::execute('DELETE FROM faqs WHERE id = ?', [$id]);
Database::transaction(function () { /* ... */ });
```
Never concatenate user input into SQL. Sort columns / table names that come from the request must be checked against a whitelist.

### Models (`App\Models\*`, frozen)
Static generic API (`find findOrFail findBy all where first count exists paginate pluck create update updateWhere delete deleteWhere uniqueSlug columns`) - see the generated reference.
`create()/update()` silently drop unknown columns and `id/created_at/updated_at`. WHERE syntax: `['col' => v]`, `['col' => [1,2]]` (IN), `['col' => null]`, `['col >=' => v]`, `['@raw' => ['published_at <= NOW()', []]]`.
`Post::paginate($request->page(), 9, ['status' => 'published'], 'published_at DESC')` returns a `Pagination` (`->items`, `->total`, `->page`, `->pages`...); render with `partial('partials/pagination', ['pagination' => $p])`.
Complex queries (joins, aggregates) go in **your own controller/service** with `Database::`.

### Forms, spam, rate limits
* Every `<form method="post">` contains `<?= csrf_field() ?>`. Public forms also contain `<?= honeypot_field() ?>` and the route has `->middleware(['honeypot', 'throttle:5,600'])`.
  The honeypot needs the form to be at least 3 seconds old (when testing with curl, `sleep 3` between GET and POST).
* `Validator` rules: `required nullable string email min:n max:n between:a,b in:a,b not_in url phone date datetime numeric integer boolean accepted confirmed same:f regex:/../ slug alpha_num unique:table,col[,ignoreId] exists:table,col array`.
* `RateLimit::attempt($key, $max, $seconds)` for custom limits. Login brute force is limited by `Auth::attempt` (5 failures / IP+email / 15 min).

### Uploads (`Uploader`)
* **Public images**: `Uploader::image($request->file('photo'))` -> relative path `YYYY/MM/<random>.<ext>` stored in the DB; show with `img_url($path)` (= `upload_url()` for uploads, `asset()` for `assets/...`).
  Limits: 5 MB, jpg/png/gif/webp, content sniffed, `svg/php/html/js...` rejected (also as a middle extension), pixel bomb check. For admin image fields use `partials/admin/image-field` + `Uploader::resolveImageField($request, 'image', $row['image'] ?? null)` (handles AJAX path, multipart fallback and removal; the replaced file is handed to `ImageCleanup::release()` AFTER the request, which deletes it only when no row, page block, rich text or setting still references it; a posted path must be a real stored image). Privacy: GD re-encodes (drops EXIF); without GD `ImageScrubber` strips EXIF/GPS/XMP/IPTC/text chunks in pure PHP and a picture that cannot be cleaned is rejected. Visitor-facing upload messages come from `site_errors` > `form.*` (editable).
* **Private files** (CVs, reports): `Uploader::privateFile($request->file('cv'), 'cv', config('upload.cv_exts'))` -> `['path','name','size','mime']` under `storage/private/` (never web accessible). Serve **only** from an
  auth-gated (or `is_public`-checked) controller with `Uploader::download($row['path'], $niceName)`. CVs: pdf/doc/docx 5 MB (`config upload.cv_exts`); documents: pdf doc docx xls xlsx ppt pptx csv txt 10 MB.
* Catch `App\Core\UploadException` and turn `getMessage()` into a validation error: `catch (UploadException $e) { $this->fail(['photo' => $e->getMessage()]); }`.
* Admin AJAX upload endpoint (foundation): `POST admin/media/upload` (field `file`, header `X-CSRF-TOKEN`) -> `{"path","url","name"}` | `422 {"error"}`.

### Sanitizer (the only way HTML reaches DB or page)
* **On save**: `Sanitizer::html($input)` for every rich-text input. **On output**: `<?= rich($row['body']) ?>` (sanitise + base-path expansion). Never `echo` raw HTML otherwise.
* Allowed tags: `p br strong em u ul ol li a h2 h3 h4 blockquote img figure figcaption hr code pre table thead tbody tfoot tr th td caption`; `iframe/script/style/svg/form` removed; `on*`, `style`, `javascript:` dropped; `<img src>` must be site-local; external links get `rel="noopener noreferrer"`.
  Internal URLs are stored root-relative (`/about`, `/uploads/2026/10/a.jpg`) and expanded to the live base path by `rich()` - so content survives moving between `/lumina` and a domain root.
* Link fields (`url` type) store `/path`, `https://...`, `mailto:`, `tel:` or `#anchor` (`Sanitizer::url()`); output with `link_url($stored)`.

### Mail, CSV, audit, logging
* `Mailer::send($to, $subject, $text, ['reply_to' => $visitor, 'html' => '<p>..</p>'])`, `Mailer::notify($subject, $text, $replyTo)` (to setting `notify_email`). Local dev writes `.eml` files to `storage/mail/`. Header-injection safe; never throws.
* `CsvExport::response('subscribers.csv', ['Email','Status'], $rows)` (formula-injection safe, UTF-8 BOM).
* `AuditLog::record('post.update', 'post', $id, 'Edited "Title"', ['fields' => [...]])` on **every admin create/update/delete/publish/export**. Naming: `<entity>.<verb>`.
* `Log::error('message', ['ctx' => 1])` -> `storage/logs/app-YYYY-MM-DD.log`.

### Auth / session
`Auth::user() check() id() role() hasRole('admin') attempt() logout() changePassword()`; helpers `current_user()`, `can('ability')`. Session cookie is httponly, SameSite=Lax, strict mode, id regenerated on login. Roles: `admin`, `editor`.
Login: every hash (real and dummy) is bcrypt cost 10 so an unknown e-mail costs the same time; the attempt row is written BEFORE the password check and counted
afterwards (parallel requests cannot slip past the 5-per-IP+e-mail / 20-per-IP limit). A password change signs every other session of that account out (the session
stores a fingerprint of the password hash). Passwords: 10-72 bytes, a letter and a number, 5+ different characters, not a common password, not containing the e-mail name.
`AuditLog` stores `Name <email>` as the actor; failed logins for unknown addresses are logged as a short hash, not as the typed text.

## 8. CMS: page registry, content blocks, pages, menus (THE OWNER'S EDITING REQUIREMENT)

**Every public page is editable from the admin without code**: headings, paragraphs, buttons (label + link), images (+ alt text), section visibility,
SEO title/description/OG image, header/footer menu entries - and the owner can create brand-new custom pages.

### 8.1 Data flow
```
app/config/pages/<slug>.php  (code: structure + DEFAULT wording)            -> PageRegistry
table pages                  (owner: title, SEO, nav flags, published, custom pages) -> SitePages (merged view of both)
table content_blocks         (owner: overrides of individual fields)         -> Content
view:  content('about','hero.title')  = saved override  ||  registry default      (site renders fully with an EMPTY database)
```
Saving a value equal to its default deletes the override (so default changes in code still flow through). "Reset to default" = delete the row.
Org-wide data (contact details, socials, donation info, branding, notify email, analytics, founder name) is in **Settings**, **not** in content blocks.

### 8.2 Registry file format (`app/config/pages/<slug>.php` returns an array)
```php
return [
  'slug'     => 'about',                     // = file name; URL-safe; unique
  'title'    => 'About Us',                  // admin label + default <h1>/title
  'route'    => '/about',                    // public path ('/' for home)
  'template' => 'default',                   // optional
  'help'     => 'Who we are, vision, mission...',            // optional hint shown in the admin
  'nav' => [                                 // DEFAULT menu behaviour (the owner can change it in the admin: stored in `pages`)
      'label'  => 'About',  'order' => 20,
      'header' => true,  'footer' => true,   // show in header / footer menu by default
      'parent' => null,                      // slug of the parent entry (header dropdown, one level)
      'button' => false,                     // true = rendered as the orange CTA button in the header (Donate)
      'requires' => ['table' => 'team_members', 'where' => 'is_active = 1'],   // HIDE the entry until this content exists
  ],
  'seo' => ['title' => 'About Lumina Africa Foundation', 'description' => '...', 'og_image' => 'assets/img/site/photo-03.jpg'],
  'sections' => [
    [ 'key' => 'hero', 'label' => 'Hero banner', 'help' => '...', 'toggle' => false,        // toggle:true => owner can hide the whole section
      'default_visible' => true,
      'fields' => [
        ['key' => 'title', 'label' => 'Heading', 'type' => 'text', 'default' => '...', 'help' => '...', 'maxlength' => 140],
        ['key' => 'lead',  'label' => 'Intro',   'type' => 'textarea', 'default' => '...', 'rows' => 4],
        ['key' => 'cta_label', 'label' => 'Button: text', 'type' => 'text', 'default' => 'Explore our Programs'],   // BUTTON = <name>_label + <name>_url
        ['key' => 'cta_url',   'label' => 'Button: link', 'type' => 'url',  'default' => '/programs'],
        ['key' => 'image', 'label' => 'Photo', 'type' => 'image', 'default' => 'assets/img/site/photo-hero-portrait.jpg', 'alt' => 'honest default alt text'],
      ]],
    [ 'key' => 'values', 'label' => 'Core values', 'toggle' => true, 'fields' => [
        ['key' => 'items', 'label' => 'Values', 'type' => 'repeater', 'item_label' => 'title', 'add_label' => 'Add a value', 'max_rows' => 12,
         'fields' => [ ['key' => 'title', 'label' => 'Title', 'type' => 'text'], ['key' => 'text', 'label' => 'Text', 'type' => 'textarea'],
                       ['key' => 'image', 'label' => 'Icon/photo', 'type' => 'image'] ],
         'default' => [ ['title' => 'Equity & Inclusion', 'text' => '', 'image' => ''], ['title' => 'Integrity & Transparency', 'text' => '', 'image' => ''] ]],
    ]],
  ],
];
```
* **Field types**: `text` (single line, tags stripped), `textarea` (plain, newlines kept), `richtext` (sanitised HTML), `image` (stored path + separate alt), `url` (`/path`, `https://`, `mailto:`, `tel:`, `#x`), `email`, `number`, `boolean`, `select` (`'options' => ['value' => 'Label']`), `repeater` (`'fields' => [...sub-fields...]`, default = list of rows; sub-fields may be any type except repeater).
* Field options: `label help default maxlength rows min max step placeholder required alt (image default alt) item_label (repeater: sub-field used as the row title) add_label min_rows max_rows options`.
* **Block key** = `<section>.<field>` (e.g. `hero.title`). Special stored keys: `<section>._visible` (`1`/`0`, only for `toggle:true` sections), `<imageField>.alt` (alt text override).
* Repeater row = associative array of sub-field values; image sub-fields also carry `<key>_alt`. Rows with no content are dropped on save.
* Registry `virtual => true` (only `global.php`): site-wide copy, no URL, no menu entry, always published.
* **Do not hardcode user-facing copy in views.** Every heading, paragraph, button label, placeholder, success/empty-state message, form label that a visitor can read must come from `content()` (registry default = the real wording), a DB row or `setting()`. Only structural/ARIA strings (`Skip to content`, `aria-label="Menu"`, `Page 2`) may be literals. Put form labels/messages in a `form` section of your registry file.
* **Never invent content.** Use only wording from the live site (`docs/live-snapshot/<page>.txt` holds the extracted text of the live pages; the live site is https://www.luminaafricafoundation.com/). Where the owner must supply real data (team, partners, reports, events, stories) build the feature fully, leave data empty, show a graceful empty state, and keep the nav entry hidden (`nav.requires`).

### 8.3 Reading content in views
```php
<h1><?= e(content('about', 'hero.title')) ?></h1>                       // text: escape
<?= nl2p(content('about', 'hero.lead')) ?>                               // textarea: escaped paragraphs
<div class="prose"><?= content_html('about', 'story.body') ?></div>      // richtext: sanitised HTML (already safe)
<?php $img = content_img('about', 'hero.image'); if ($img['has']): ?>
   <img src="<?= e($img['src']) ?>" alt="<?= e($img['alt']) ?>" loading="lazy">          // ['src','alt','path','has']
<?php endif; ?>
<?php $b = content_btn('about', 'hero.cta'); if ($b['has']): ?>                          // reads hero.cta_label + hero.cta_url
   <a class="btn btn--accent" href="<?= e($b['url']) ?>"><?= e($b['label']) ?></a>        // ['label','url','has','external']
<?php endif; ?>
<?php foreach (content_list('about', 'values.items') as $row): ?>                        // repeater rows; image: img_url($row['image']), alt: $row['image_alt']
   <h3><?= e($row['title']) ?></h3>
<?php endforeach; ?>
<?php section_begin('about', 'values', ['class' => 'section--tint', 'container' => 'container--narrow']); ?>   // prints nothing when the owner hid the section
   ...markup...
<?php section_end(); ?>                                                  // wraps in <section id="values" class="section section--tint"><div class="container container--narrow">
```
`section_begin` opts: `class`, `container` (extra container class), `id` (default = key with `-`), `bleed` (no `.container`), `attrs`, `labelledby`. `content()` returns typed values (bool for `boolean`, int|float for `number`, array for `repeater`). Values are cached per page per request (one query).
Dynamic data (programs, posts, team...) comes from the DB tables; the registry holds the *copy around it* (headings, intros, empty-state text, button labels).

* Every save: `AuditLog::record(...)`, flash message, redirect (PRG).

```php

<?php section_end(); ?>
<?= partial('partials/cta-donate') ?>
```
  Empty data -> `partial('partials/empty-state', ['title' => content(...), 'text' => content(...)])`, never a blank gap or an error.
* Public POST handler skeleton:
```php
$router->post('/contact', [ContactController::class, 'send'])->middleware(['honeypot', 'throttle:5,600']);
public function send(Request $request): Response {
    $data = $this->validate(['name' => 'required|max:150', 'email' => 'required|email', 'message' => 'required|max:5000'], [], ['name' => 'Name']);
    ContactMessage::create($data + ['ip' => $request->ip(), 'user_agent' => $request->userAgent()]);
    Mailer::notify('New contact message', "From {$data['name']} <{$data['email']}>\n\n{$data['message']}", $data['email']);
    Flash::success((string) content('contact', 'form.success'));
    return $this->redirect('contact');
}
```
  Form markup: `<form method="post" action="<?= e(url('contact')) ?>" novalidate>` + `csrf_field()` + `honeypot_field()` + `partials/form-field` for each input (it shows errors + old input) + `<button class="btn btn--primary" type="submit">`. `main.js` disables the submit button after the first submit.
* Admin CRUD skeleton (every admin area follows the same shape; URLs in section 16):
  `index` (filters form `.filters` + `.table-wrap > table.table` + `partials/pagination`), `create`/`edit` (one shared `_form.php` partial in your views folder, `.card` + `.form-grid`, `partials/form-field`, `partials/admin/image-field`, `partials/admin/richtext-field`, sticky `.form-actions`), `store`/`update` (validate -> save -> `AuditLog` -> `Flash::success` -> redirect), `delete` (POST, `data-confirm`). Page header via `partials/admin/page-header`. Status pills via `partials/admin/status-badge`. Delete buttons always `<form method="post" action=".../delete" data-confirm="Delete this item?">` + `csrf_field()`.
  Delete image/private files with `Uploader::delete()` / `Uploader::deletePrivate()` when the row is deleted or the file replaced.
* **Role checks on every admin route/controller method**: `$this->authorize('content.manage')` (or `inbox.manage`, ...). `editor` may do content/inbox work but **not** delete inbox data (`inbox.delete`), manage users/settings/menus, or view the audit log.
* Pagination/search inputs come from `$request->query()`; whitelist sort columns; always bind parameters.

## 13. SCSS system (`scss/`)

* `scss/main.scss` -> `assets/css/main.css/.min.css` (public). `scss/admin.scss` -> `assets/css/admin.css/.min.css` (admin; it re-imports the shared `components/buttons forms badge alerts pagination breadcrumbs filter-bar`, so `.btn .field .input .badge .alert .pagination .empty-state` look right in admin too).
* **libsass 3.6: `@import` only** (no `@use/@forward/sass:math`, no `math.div`). Division: `($a / $b)`. **Do not write `min()/max()/clamp()` with mixed units** directly (libsass evaluates them): use `fluid(1.5rem, '1rem + 2vw', 2.5rem)` or `#{'min(100%, 20rem)'}`.
* **Your own SCSS goes only in your partials**, already imported by `main.scss`/`admin.scss`: `scss/pages/_<page>.scss` (public) and `scss/admin/_<area>.scss` (admin). Scope every rule under a page class (`.page-team { ... }`; the layout adds `page-<slug>` to `<body>`, and `$bodyClass` adds more) and reuse tokens/mixins/components. ## 18. Security rules every agent MUST follow

1. **Escape all output**: `e()`; HTML only via `rich()` / `content_html()`; never `echo $_GET/$_POST`; never build HTML from user input without `e()`.
2. **Prepared statements only** (`Database::` / `Model::`). Whitelist anything that becomes an identifier (sort column, table).
3. **CSRF on every POST** (`csrf_field()`; the router verifies automatically). State changes **only** via POST (never GET). AJAX sends `X-CSRF-TOKEN`. Validators reject array values for scalar fields; `Request` repairs invalid UTF-8 once, so controllers never see it.
4. **Public forms**: `honeypot_field()` + middleware `honeypot` + `throttle:N,S`, server-side `validate()`, length limits, store `ip` + `user_agent`. Success message from `content()`.
5. **Admin**: every route inside `auth`; every controller method `authorize()`s an ability; destructive actions need `data-confirm` and POST; log with `AuditLog::record`.
6. **Uploads**: only through `Uploader` (images: public; CVs/reports: private + auth-gated or `is_public` download controller). Never trust client file names/MIME. Never store uploads outside `uploads/` or `storage/private/`.
7. No raw HTML except through `Sanitizer`. No inline `<script>`/`on*`. No secrets in code or chat. No hardcoded `/lumina`. No hardcoded user-facing copy.
8. **No new public content that the owner cannot edit.** Impact stories: publish only with `consent_confirmed = 1`; never show a person's story/photo/contact details without consent. Team/partner/donor data is empty until the owner adds it.
9. Redirect after POST (PRG) with `Flash::success()`. Validation errors go through `ValidationException` (old input is never flashed for password fields).
10. Accessibility: one `<h1>` per page, labels for inputs (`form-field` does this), `alt` text on every informative image (from `content_img()` / DB `image_alt`), visible focus, buttons vs links used correctly, no colour-only meaning, respect reduced motion.
